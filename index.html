Primary project · Sim ↔ Real fidelity

Digital Twin & Simulation Fidelity Framework

Isaac Sim 5.x · PhysX · ros2_control · UR RTDE

Built a high-fidelity digital twin of the full mobile manipulator — swerve base, lift, 6-DoF arm, tools, and spray hose — and validated real-vs-sim equivalence across kinematics, dynamics, sensors, and control. The bar wasn't "looks right"; it was a quantitative spec sheet with tolerances.

  • Defined an equivalence framework with strict tolerances — mass <2%, joint angle <0.5°, time drift <10 ms/min, swerve speed error <2%, lift travel error <2 mm.
  • Modelled spray-hose dynamics end-to-end — mass distribution, bending stiffness, damping, friction, contact, occlusion — and matched real swing-decay and TCP disturbance behaviour within ±20%.
  • Validated ros2_control + UR RTDE @ 500 Hz for trajectory tracking, force disturbances, and the URSim protective-stop / recovery pipeline at <100 ms latency.
  • Engineered behavioural parity for collision detection, protective stops, and recovery across self-collision, environment-collision, and false-positive filtering — 100% trigger on valid collisions, zero spurious stops on nominal motion.
  • Tuned PhysX actuators, encoders, and saturation models for both lift and swerve modules against real CSV logs — settling times and RMS tracking errors within ±20% of hardware.
  • 500 HzUR RTDE
  • <10 msclock drift / min
  • <2%mass / speed error
  • 100%collision parity

Distributed systems · Edge compute

Distributed HIL Pipeline — Isaac Sim × Dual Jetson Orins

Isaac Sim · AGX Orin + MiiVii Orin · CycloneDDS · GStreamer / V4L2

Architected a hardware-in-the-loop pipeline that mirrors the production deployment topology — a sim workstation streaming sensor data over a managed switch into a Planner Orin (perception, Nav2, MoveIt2) and a Controller Orin (ros2_control, safety, RTDE). The point: surface every cross-machine, ARM64, and thermal failure mode before it shows up on a job site.

  • Implemented driver-level sensor emulation instead of ROS2 topic passthrough — cameras over RTP into v4l2loopback, RoboSense Airy as proprietary MSOP/DIFOP UDP, YDLIDAR GS2 over emulated UART. Production drivers (DeepStream, rslidar_sdk, YDLIDAR SDK) run unmodified on the Orins.
  • Eliminated DDS as the bandwidth bottleneck by pushing high-rate sensor data off DDS entirely — sustained ~2.24 Gbps wire throughput while DDS carries only small, latency-critical control traffic.
  • Achieved RTF ≥ 1.0 headless and <25 ms end-to-end control-loop latency under the full v2 sensor load (6 cameras @ 1080p10, 2× 96-channel lidars, IMU, safety lidars, RTDE @ 500 Hz).
  • Validated system-level health — per-topic latency budgets, jitter distributions, /clock drift <10 ms over 1-hour soaks, thermal stability of both Orins under MAXN load.
  • Specified the QoS strategy, CycloneDDS unicast peer config, jumbo-frame tuning, and recovery behaviour for cable-disconnect and process-restart scenarios (recovery <5 s).
  • ~2.24 Gbpssustained throughput
  • <25 mse2e control latency
  • RTF ≥ 1.0real-time factor
  • 2× OrinPlanner + Controller

Motion planning · Design validation

Tool Coverage Testing Pipeline

MoveIt 2 · TRAC-IK · FCL / PhysX · trimesh · Isaac Sim

Built a quantitative pipeline to answer a deceptively simple question: of every square metre of drywall on a real construction site, how much can the robot actually reach with a given tool? It turns mechanical-design iterations into measurable coverage deltas instead of intuition.

  • Defined a quantified coverage metric — feasible TCP poses over total drywall area — with per-failure-mode breakdown (IK failure, self-collision, environment collision, docking-clearance violation).
  • Ran large-scale IK + collision feasibility across the 9-DoF system (base x/y/yaw + lift + UR10e 6-DoF) using TRAC-IK with FCL collision under MoveIt 2.
  • Processed 50k–100k surface points per site via uniform mesh sampling, with TCP-pose generation per tool clearance (200–300 mm sprayer, 50 mm sander).
  • Validated solver and collision accuracy at the unit level — <2 mm TCP error, 100% collision-detection accuracy, ±0.5 mm offset accuracy — before scaling.
  • Defined a fast-feedback test set of geometric edge cases (recessed beams, multi-planar walls, beam-wall gaps, ducts, closets) for sub-hour mechanical-design sanity checks before running the full 100-site sweep.
  • 9 DoFfull-system IK
  • 50–100kpoints / site
  • 100 sitestarget coverage sweep
  • <2 mmTCP solver accuracy
